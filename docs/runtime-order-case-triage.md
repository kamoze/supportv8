# AgenticOS Runtime order-case triage

`POST /api/v1/runtime/order-case-triage` is a narrow SupportV8 handoff for an accepted OrderV8 customer follow-up. Runtime must first verify its signed-in manager, the OrderV8 case receipt, and Sophia's exact active Registry installation and Forge hire. The browser cannot call SupportV8 directly. SupportV8 accepts only an allowlisted Runtime workload token with audience `supportv8`, scope `supportv8:runtime:order-triage`, and matching account/tenant headers and token claims when present. It checks that its tenant is bound to that ServiceV8 account and domain.

The request contains only the OrderV8 case reference, its receipt, Runtime objective ID, response due time, tenant domain, and Sophia installation/hire IDs. It does not carry customer name, contact method, call transcript, or issue text. SupportV8 searches this tenant's active approved knowledge articles for delayed-order guidance. If none is available, it returns `approved_support_guidance_unavailable` and creates no ticket. With guidance, it creates one SupportV8 issue linked to the OrderV8 case and records an idempotent receipt in `supportv8.runtime_order_handoffs`. The issue uses the generic label “OrderV8 customer”; the customer record remains in OrderV8. A retry returns the original ticket and receipt, even if the knowledge article is temporarily unavailable. A changed objective or Sophia binding for the same case is rejected.

Apply `migrations/004_runtime_order_handoffs.sql` and grant the `supportv8_app` role scoped table DML before enabling this route. Set `SUPPORTV8_RUNTIME_WORKLOAD_ISSUER`, `SUPPORTV8_RUNTIME_WORKLOAD_CLIENT_IDS`, and optionally `SUPPORTV8_RUNTIME_WORKLOAD_JWKS_URL`; provision the corresponding short-lived workload scope. The current GitOps SupportV8 database bootstrap does not yet include this table, so a live rollout must update that bootstrap and verify RLS, migration order, and app-role grants. No live deployment is claimed by this document.

This handoff creates a real case-linked support ticket through SupportV8. It is an explicit manager action in AgenticOS Chat. It does not transfer the customer call, close the OrderV8 case, or prove Sophia has spoken; those voice and completion receipts remain separate.
