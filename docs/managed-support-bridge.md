# Managed Support source-owned native boundary

`POST /internal/service-apps/support/invoke` is workload-only. Control operations `connection.verify`, `connection.readiness` and `connection.lifecycle` retain the existing exact immutable target and data-free behavior.

Lookup accepts exactly `{target,operation:'support_ticket_lookup',source:{kind:'runtime',invocationId,digest},parameters:{ticketRef}}` under `supportv8:tickets:read`. The owner independently reads fixed Runtime `/internal/support-invocations/verify`, validates the complete canonical invocation/digest/expiry and originating Runtime client, and matches target, deterministic connection and exact reference. It independently reads Registry's selected `runtime_chat` configured policy, including current canonical employee and channel generation, with `dataReady:false`. It then calls the native `resolveOperationalSupportAccess` for the proof's subject and exact Support workspace, using the injected Registry transport and PostgreSQL client. Existing OWNER/ADMIN support:manage and MANAGER/STAFF/MEMBER support:read capabilities explicitly permit the lookup, intersected with channel permission `support.tickets.read`. Unknown roles, membership loss, absent/changed policy or unavailable authority deny.

Only after this authorization does the existing RLS exact external-reference query run. Zero/ambiguous matches return no ticket. Output contains only reference/status/priority. No summary, customer identity, internal IDs, list or mutation is exposed.

`support_output_access` accepts exactly `{target,operation:'support_output_access',source:{kind:'runtime',disclosureId,digest}}` under separate `supportv8:output:authorize`. Its separate Runtime disclosure proof binds initial_delivery/history_replay, original thread/turn/invocation/result provenance and a fresh deadline. The owner checks current configured policy and native RBAC, and returns only `{ok:true,target,disclosureId,digest,allowed:true}`. It never queries tickets. An expired/completed lookup cannot pass the invocation verifier; later history needs a fresh same-subject Runtime disclosure admission. Runtime is responsible for session/cancellation checks and guarding every persisted/derived output before model context or delivery.

## Workload configuration

- Existing `SUPPORTV8_MANAGED_WORKLOAD_ISSUER/JWKS_URL/CLIENT_IDS` supplies trusted issuer/audience/union clients. Data and output additionally require `SUPPORTV8_MANAGED_DATA_CLIENT_IDS` (Gateway owner client). Data/output JWTs are <=120 seconds with exact distinct scope, verified azp, standard claims and optional validated nbf. No dynamic grant/actor claims or token exchange.
- Fixed Runtime origin `SUPPORT_RUNTIME_URL`; proof-reader credentials `SUPPORTV8_SOURCE_TOKEN_URL/CLIENT_ID/CLIENT_SECRET`; originating Runtime clients `SUPPORTV8_RUNTIME_INVOCATION_CLIENT_IDS`. Reader audience is `servicev8-agentic-runtime`, exact `runtime:support-invocation:verify` or `runtime:support-disclosure:verify`.
- `REGISTRY_URL` and existing `SUPPORTV8_MANAGED_TOKEN_URL/CLIENT_ID/CLIENT_SECRET` serve the separate configured projection, audience `servicev8-registry`, exact `registry:support-context:read`. New token responses are <=120 seconds. Fixed callbacks and policies are bounded to16KiB/five seconds, no redirects/cache; credential endpoints HTTPS, internal Registry origins include `registry-service.default.svc.cluster.local`.
- Native operational RBAC retains `SERVICEV8_OIDC_ISSUER`, `SUPPORTV8_RUNTIME_REGISTRY_CLIENT_ID/CLIENT_SECRET` for fresh membership/installations. Its transport receives the same injected env/request as the managed owner; local authority uses the same injected PostgreSQL client.

Missing source callbacks, configured policy or owner permission fail closed. Provider inbound voice remains denied. ## Permanent managed connection lifecycle

Migration 009 makes ready registration jobs eligible for periodic observation (five minutes after a successful reconciliation). The worker first observes the exact local native workspace while holding its registration lease. Only `state = tombstoned AND deleted_at IS NOT NULL` on that immutable account/Registry tenant/Runtime installation/native workspace tuple changes desired state to `permanently_revoked` and increments the job generation once. Retries preserve generation; a stale lease cannot observe or finish. This generation is unrelated to employee grant policy generations.

The owner operation `connection.lifecycle` requires `supportv8:managed:lifecycle` through the existing issuer/audience/client allowlist. It freshly rereads the exact local tombstone and its persisted observation. Registry has no trusted exposed terminal marker: suspension, expired plans, non-ready installations, missing projections, and Registry failures cannot supply permanent proof. Active/temporary results have generation zero. Only the local observed tombstone returns `permanently_revoked`, generation one, reason `workspace_tombstoned`.

The worker calls Gateway `/v1/support/managed/disable` with `action:support:lifecycle`, the deterministic connection ID and persisted generation. Gateway independently obtains owner proof. Only an exact disabled acknowledgement advances applied generation and marks the job revoked. Failed or lost replies stay retryable. If the connection was never created, disable remains pending without creating a connection. There is no re-enable or historical acquisition replay in this slice.
